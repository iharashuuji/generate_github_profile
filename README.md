# GitHub Profile 自動化ハンズオン

このリポジトリは、**GitHub Profile（`github.com/<あなたのユーザー名>` に表示される自己紹介ページ）を、
自分の手で育てながら Git / Linux / CI/CD / Docker を学ぶ**ための教材スターターです。

---

## 📖 この講座の理念

> **学んだ技術を、その場で自分のポートフォリオ（GitHub Profile）に反映して育てる。**

技術書を読んで終わりではなく、学んだその日に「自分の GitHub を訪れた人に見えるもの」が
変わっていく。この実感が、技術を定着させる一番の近道です。

この README.md 自体が、3 回の演習を通じて
**「手書きの自己紹介」から「自動生成されるポートフォリオ」へ**進化していきます。

---

## 🗺 全3回の全体像

| 回 | テーマ | 演習の意図 | README を更新するのは誰か |
|---|---|---|---|
| **[Day 1](docs/DAY1.md)** | Git / GitHub 基礎 | 環境構築ゼロで開発を始め、「ブランチ → PR → マージ」を体得する | **あなた**（手で編集） |
| **[Day 2](docs/DAY2.md)** | Linux & GitHub Actions | 手動更新から動的生成・自動コミット（CI/CD）へ進む | **Bot**（Actions が実行） |
| **[Day 3](docs/DAY3.md)** | Docker & コンテナ自動化 | 環境依存を克服し、どこでも同じ結果になる状態を作る | **Bot が、コンテナの中で** |

### 各回の背景（なぜ学ぶのか）

- **Day 1** … 個人開発でも `main` への直接 Push を避け、**PR で差分を確認してからマージする癖**を
  つけることが、安全な開発の第一歩となるためです。
- **Day 2** … Linux CLI の基本を学んだうえで、その先にある**自動化の世界（GitHub Actions による代行）**に
  触れ、運用の自動化（GitOps）の入口を体験するためです。
- **Day 3** … Day 2 で作った `generate.sh` を**コンテナの中で動かす**ことで、
  CI/CD パイプラインが持つ「**環境の一致**」という性質を自分の手で確認するためです。

## 🚀 はじめかた

### Step 1：このリポジトリを自分のアカウントにコピーする

このリポジトリは **Template Repository** です。`Fork` ではなく **`Use this template`** を使います。

1. **`Use this template`** → **`Create a new repository`** をクリック
2. **Owner** … 必ず**自分の個人アカウント**を選択
3. **Repository name** … **自分の GitHub ユーザー名と完全に一致させる**
4. **Public** を選択
5. `Create repository` をクリック

> ### ⚠️ 重要 1：リポジトリ名はユーザー名と完全一致させること
>
> GitHub には「**ユーザー名と同じ名前のリポジトリの README.md を、
> プロフィール画面に表示する**」という公式機能（Profile README）があります。
> ユーザー名が `octocat` なら、リポジトリ名も `octocat` です。
> `octocat-profile` のように余計な文字を足すと機能しません。
> また、**Private では表示されません。**

> ### ⚠️ 重要 2：必ず「個人アカウント」配下に作成すること
>
> GitHub Codespaces の**無料枠（月 120 コア時間・15 GB ストレージ）は、
> 個人アカウントにのみ適用されます。**
>
> **組織（Organization）アカウント配下にコピーすると、初回の起動から課金対象になります。**
> 作成前に、Owner の欄が会社名やチーム名になっていないか必ず確認してください。

### Step 2：Codespace を起動する

**この講座では、ローカル PC に開発環境を作りません。**
Docker Desktop も WSL も不要です。すべてブラウザ上の GitHub Codespaces で完結します。

1. コピーして作られた**自分のリポジトリ**を開く
2. 緑色の **`Code`** ボタンをクリック
3. **`Codespaces`** タブを選択
4. **`Create codespace on main`** をクリック

ブラウザ上に VS Code が立ち上がれば準備完了です（初回は 1〜2 分かかります）。

## 🧹 使い終わったら：Codespace を必ず削除する

> **「停止」と「削除」は別物です。**
> **停止しただけでは、ストレージ枠を消費し続けます。**

<https://github.com/codespaces> → 該当 Codespace の **`...`** → **`Delete`**

`git push` 済みの変更は GitHub 上に残るため、削除しても失われません。
詳しい手順は各 DAY ドキュメントの末尾に記載しています。

