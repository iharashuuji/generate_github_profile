# Day 1：Git / GitHub 基礎 — PR駆動開発と Codespaces

## 1. この回で学ぶことと演習の意図

### この講座全体の理念

> **学んだ技術を、その場で自分のポートフォリオ（GitHub Profile）に反映して育てる。**

技術書を読んで終わりではなく、学んだその日に「自分の GitHub を訪れた人に見えるもの」が
変わっていく。この実感が、技術を定着させる一番の近道です。

### Day 1 の意図

**Codespaces 上で環境構築ゼロで開発を開始し、チーム開発のデファクトスタンダードである
「トピックブランチ作成 → PR → マージ」のフローを体得する。**

### なぜこれを学ぶのか（背景）

個人開発でも `main` ブランチへの直接 Push を避け、**PR（Pull Request）で差分を確認してから
マージする癖をつけること**が、安全な開発の第一歩となるためです。

実務では、次のような理由から PR が必須になります。

| 観点 | main 直 Push | PR 経由 |
|---|---|---|
| レビュー | 誰も差分を見ない | マージ前に他人（or 未来の自分）が差分を確認できる |
| 巻き戻し | 履歴から探すのが大変 | PR 単位でまとめて revert できる |
| CI | 壊れたコードが main に入る | マージ前にテスト・Lint を走らせられる |
| 記録 | commit しか残らない | 「なぜこの変更をしたか」の議論が残る |

「一人だから PR はいらない」ではなく、**一人のうちに手が覚えるまで練習しておく**のが
このDayのねらいです。
