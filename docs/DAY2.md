# Day 2：Linux & GitHub Actions 基礎 — 動的生成と自動化

## 1. この回で学ぶことと演習の意図

### この講座全体の理念

> **学んだ技術を、その場で自分のポートフォリオ（GitHub Profile）に反映して育てる。**

### Day 2 の意図

**手動更新から「プログラムによる動的生成（シェルスクリプト）」および
「クラウド上での自動コミット（CI/CD）」へステップアップする。**

第一回では、README.md を**あなたの手で**書きました。
今回は、その README.md を**スクリプトが自動で書く**ようにします。
さらにそのスクリプトを、**あなたの PC ではなくクラウド上（GitHub Actions）で動かします。**

### なぜこれを学ぶのか（背景）

Linux CLI の基本（`pwd` / `ls` / `cd` / `cp` / `rm` / `mv` / `cat` / `nano` / `mkdir`）を
学んだうえで、その先にある自動化の世界——**GitHub Actions（Bot）による代行**——に触れることで、
**運用の自動化（GitOps）の入口**を体験するためです。

実務では「手で毎回やっていた作業」を、次のように移していきます。

| 段階 | 誰がやるか | 今日どこを体験するか |
|---|---|---|
| 手作業 | 人間が毎回ファイルを編集 | ← 第一回でやったこと |
| スクリプト化 | 人間がコマンドを1回叩く | ← `generate.sh` を実行してみる |
| 自動化（CI/CD） | **Bot が勝手にやる** | ← **今日のゴール** |

「更新を忘れる」「更新の仕方を忘れる」「担当者が辞めて誰も更新できない」——
運用でよく起きるこれらの問題は、**自動化そのものをコードとしてリポジトリに置く**ことで解決します。
これが GitOps の考え方です。

### 今日のゴール

> `main` に push した瞬間、**GitHub 上の Bot** が `generate.sh` を実行し、
> README.md を自動で書き換えてコミットしてくれる。
> その結果が **Profile 画面**と **GitHub Pages** の両方に反映される。

### ⚠️ スコープについて（重要）

**`generate.sh` の中身（`sed` / `date` / `curl`）は配布済みコードとして提示するのみです。
受講者のみなさんが書いたり、改造したりする必要はありません。**

> **このコードは配布済みです。中身を全部理解できなくても心配ありません。
> 今日のゴールは、このコードが Actions 上で実行され、
> Profile と Pages の両方が自動で更新される様子を体験することです。**

コードの解説は講義で行います。手を動かすのは「実行して、結果を見る」ところに集中してください。
